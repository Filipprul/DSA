# Grundidee
Die Komplexität beschreibt den Ressourcenverbrauch eines Algorithmus. Da
Camputer heute sehr viel Arbeitsspeicher haben, konzentrieren wir uns meistens
auf die Zeitkomplexität. Wie viel länger braucht das Programm, wenn ich ihm
statt 10 plötzlich 1 Million Daten gebe?

Das Ziel ist immer Effizienz: Ein guter Algorithmus löst das Problem nicht nur,
er tut es mit dem geringsten Aufwand an Zeit und Speicher.

# Die Big O Notation (Groß-O-Notation)
Um die Effizienz vergleichbar zu machen, nutzen wir das Symbol O. Es beschreibt
das "Worst-Case-Szenario" (die obere Schranke). Wir schauen uns an, wie die
Laufzeit im Verhältnis zur Eingabegröße n wächst.

# Die wichtigsten Klassen:
1. O(1)-Konstante Zeit: Egal wie groß n ist, es dauert immer gleich lang.
   - Beispiel: Den ersten Namen aus einer Liste lesen.

2. O(n)-Lineare Zeit: Die Dauer wächst exakt mit der Anzahl an Daten.
   - Beispiel: Eine Liste einmal von vorn bis hinten durchlesen.

3. O(n²)-Quadratische Zeit: Verdoppelt sich n, vervierfacht sich die Zeit.
   - Beispiel: Bubble Sort (jeder wird mit jedem verglichen).

4. O(log n)-Logarithmische Zeit: Extrem effizient. Selbst wenn n riesig wird,
   steigt die Zeit nur minimal.
   - Beispiel: Binäre Suche in einem sortierten Telefonbuch.

# Zeit vs. Speicher (Time vs. Space)
Ein Algorithmus kann in zwei Kategorien analysiert werden:
- Time Complexity (Zeit): Wie viele Rechenschritte werden ausgeführt?
- Space Complexity (Platz): Wie viel zusätzlicher Arbeitsspeicher wird während
  der Rechnung belegt?

Wichtig: Oft gibt es einen "Trade-off". Man kann ein Programm schneller machen,
indem man mehr Speicher verbraucht (z.B. durch Zwischenspeichern von
Ergebnissen), oder Speicher sparen, indem man länger rechnet.

# Warum ist das wichtig?
Ein Algorithmus mit O(n²) mag bei 100 Elementen noch schnell wirken.
Bei 1 Million Elementen würde er aber Jahre brauchen, während ein O(n*log n)
Algorithmus dieselbe Aufgabe in Sekunden erledigt.

# Aufgaben
## Level 1-Verständnis
Ordne folgende Szenarien der passenden Komplexität zu (O(1), O(n) oder O(n²)):
1. Du suchst eine Socke in einem ungeordneten Haufen von n Socken.
2. Du schaust nach, ob das Licht in einem Raum an oder aus ist.
3. Du vergleichst jede Socke im Haufen mit jeder anderen Socke, um alle Paare zu
   finden.

## Level 2-Analyse
```java
for (int i = 0; i < n; i++){
    for (int j = 0; j < n; j++){
        System.out.println("Hallo");
    }
}
```
Frage: Welche Zeitkomplexität hat dieser Code in Big O Schreibweise? Begründe
kurz.

## Level 3-Anwendung
Du hast die Wahl zwischen zwei Algorithmen, um 10.000 Datensätze zu sortieren:
- Algorithmus A: O(n²)
- Algorithmus B: O(n⋅log n)

Berechne grob den Unterschied der Rechenschritte (n² vs. n⋅log n mit Basis 10
für die Logik).
Warum würdest du im professionellen Umfeld fast immer Algorithmus B wählen?
